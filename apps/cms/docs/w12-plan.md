## 4. Schema and API contract (B builds exactly this; others consume it)

Articles (new fields, all optional so existing content stays valid):
- `kicker` text (max 60), `contentType` select `news|analysis|opinion|sponsored|explainer|factcheck` (default `news`; legacy rows null => `news`).
- `keyPoints` array of `{ text }` (max 5 items, 200 chars each).
- `lastSubstantiveUpdate` date (shown as "Updated"; editor-set, never auto).
- `topics` relationship hasMany -> `topics`.
- `bylineAuthor` relationship -> `authors` (optional; `bylineName` text stays as fallback).
- Lexical blocks added to the article editor: `pullQuote` ({ quote, attribution }) and `gallery` ({ images[] of media with alt+caption, max 12 }).
- `readingMinutes` is NOT stored; the public layer computes it (words / 220, min 1).

New collections:
- `authors`: name, slug (unique), role, bio (text, 600 max), photo (media, optional), socials (array of { kind select x|facebook|instagram|linkedin|website, url }), `isPublic` bool. Public read via `/api/public/authors` and `/api/public/authors/:slug` (profile + their latest 20 published articles as the standard card shape).
- `topics`: name, slug (unique), kind select `topic|denomination|series|ministry`, description (400 max), `isPublic`. Public: `/api/public/topics`, `/api/public/topics/:slug` (topic + latest 20 published articles, card shape), `/api/public/topics/:slug/feed.xml` optional.
- `donations`: `reference` (unique, server-generated), `provider` select `paystack|flutterwave`, `amountMinor` number (kobo/pence/cents), `currency` select `NGN|USD|GBP|EUR`, `status` select `pending|succeeded|failed|abandoned`, `channel` text, `cause` select `general|relief|ministry` (default `general`), `email` text (optional), `name` text (optional), `anonymous` bool, `consentAt` date (NDPA consent timestamp), `receiptSentAt` date, `providerRef` text, `paidAt` date. NO card data, NO full webhook payloads stored. Admin-only access (no public read); retention note in docs.
- `newsletter-issues`: `date`, `subject`, `status` select `draft|sending|sent|failed`, `bodyText`, `bodyHtml`, `sentCount`, `failedCount`, `capApplied` bool, `lastError`. Admin/editor-managed.

Media (new): `lqip` text (tiny base64 blur data URI, max 1,500 chars), new image sizes `cardAvif` (800 w, avif) and `heroAvif` (1600 w, avif) next to the existing webp sizes. B adds them; Agent C consumes them.

Globals:
- `giving-settings`: `enabled` (default false), `provider`, `currencies` (array of { currency, presets[] minor units, minimum, maximum, label }), `causes` (array of { key, label, enabled }), `thankYouNote`, `bankTransferNote`.
- `newsletter-settings`: `enabled` (default false), `dailyDigestEnabled`, `sendHourLagos` (0-23), `dailySendCap` (default 100, hard stop), `fromName`, `replyTo`, `maxStoriesPerDigest` (default 6), `includeDevotional` bool.
- `site-trust` (for Agent A's trust pages): `editorialStandards` (rich text), `ownershipFunding` (rich text), `ethicsCorrectionsPolicy` (rich text), `contactEditors` text. Public: `/api/public/site-trust`.

Public API additions (read-only, rate-limited like the other public endpoints, same CORS/origin rules, same card shape as existing list endpoints; B documents exact JSON in `apps/cms/docs/w12/schema-contract.md` and pushes it first):
- Existing article payload (`/api/public/...` list + detail) additionally exposes `kicker`, `contentType`, `keyPoints[]`, `lastSubstantiveUpdate`, `topics[{name,slug}]`, `author {name,slug,photo?}` (when `bylineAuthor` set), `featuredImage.lqip`, avif sizes, pullQuote/gallery blocks in the rendered content blocks.
- `POST /api/public/giving/init`, `POST /api/public/giving/webhook/:provider`, `GET /api/public/giving/status?reference=`, `GET /api/public/giving/settings` (public-safe fields only) are owned by Agent D (D adds endpoint files and registers them; B creates the `donations`/`giving-settings` schema they use).
- `POST /api/public/newsletter/...` (existing signup) stays; unsubscribe and digest endpoints are owned by Agent E.

Newsroom (apps/newsroom, owned by B): editor fields for kicker, contentType, key points (max 5), lastSubstantiveUpdate, topics, author profile, pull quote/gallery blocks as far as the newsroom editor supports blocks; admin screens in the CMS admin for donations (read-only list + CSV export without email columns unless admin), newsletter issues. Keep the four-eyes and existing roles intact: reporters never publish.
