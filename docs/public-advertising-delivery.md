# Direct advertising delivery (Wave 2 B4)

## Direct advertising

`VITE_PUBLIC_ADVERTISING_URL` explicitly opts into C3 anonymous delivery. HTTPS is required except loopback development HTTP; credentials/query/fragment are rejected. The delivery module loads lazily only when configured. Requests are ordinary GETs with `credentials: 'omit'`; the browser handles HTTP caching. No browser code reads ETag or sets `If-None-Match`, so no custom conditional header triggers an unsupported CORS preflight. Concurrent loads coalesce. The local snapshot expires at the earliest of 60 seconds, the response's `max-age`, and the next supplied campaign start/end. The endpoint's shorter `max-age` also accounts for future campaigns absent from the active-only projection. Failures yield no placement and briefly back off. AdSense remains inert regardless of response flags; no scripts, tracking pixels or guessed publisher IDs are supplied.

Routes render **synchronously before advertising delivery**. A delayed response never rerenders the page or resets focus. Each request captures the current route's abort signal and markers, so a response for a previous route cannot populate the current route. A fresh cached snapshot can mount synchronously during the new route's construction, reserving the approved creative dimensions immediately. On a cache miss, markers reserve **zero space** until a validated advert exists. When the response arrives, only markers below the viewport are filled. Visible or already-passed opportunities are skipped for that view, rather than pushing visible editorial content down; cached data can serve them on the next navigation. This trades some impressions for stable reading and no unsold gaps. No empty billboard area is reserved speculatively.

Existing campaign/date/dimension/URL validation is unchanged. In particular `mobile-banner` remains **320×50**, matching corrected C3. Once a slot is inserted, its width/height and existing fixed-aspect creative CSS reserve space before the image arrives. Failed images remove their slot. The existing renderer checks campaign dates again at mounting. A paused or cancelled campaign can remain in a cached snapshot for up to 60 seconds plus intermediary cache delay, as stated in C3; a newly-private creative collapses on image failure. No impression/click counters are introduced.

## Validation and scope

Unit tests use **synthetic response stubs** for request headers, anonymous GETs, coalescing, start/end/cache-age boundaries, invalid configuration, malformed data, failed transport, HTTP 403/503 and unsupported 304. Browser tests run against **synthetic C3 and creative stubs** on desktop and Pixel 7: content/focus while the request is held, navigation before delivery, below-fold mounting, cached navigation, visible-marker suppression, no gap and CLS ≤0.1, plus malformed-payload failure with zero page errors and zero console errors. The malformed-payload browser test deliberately uses HTTP 200: an HTTP 503 can produce Chromium's own network-resource console diagnostic even when application code catches it; HTTP failures are separately covered by unit stubs.

These checks are not proof of the real CMS endpoint or production advertising readiness. Claude's real Payload/PostgreSQL cross-app journey remains required. No CMS/newsroom, production, hosting or owner advertising decision changes are included. The shared submission fieldset readiness fix already on this branch is retained and named in the PR; it is independent of delivery. This feature PR restores `site/**` and the root `index.html` to the integration baseline. A dedicated rebuild after source integration will publish the combined assets; these stub results do not claim that a static exported bundle already contains the feature.

Source-only validation depends on [PR #57](https://github.com/abcentech/churchtimes/pull/57), whose policy commit is included here. CI builds the actual feature source and checks its compiled assets; it does not claim that the pending committed Pages export matches. Main and dedicated rebuild branches retain strict export checks.
